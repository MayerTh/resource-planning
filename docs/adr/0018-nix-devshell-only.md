# ADR 0018: Nix flake scoped to dev-shell only; Docker is the packaging/distribution mechanism

- Status: accepted
- Date: 2026-10-11
- Narrows the Nix role from [ADR 0009](0009-confirm-java-maven-nix-stack.md); complements [ADR 0017](0017-separate-artifacts-quarkus-web-editor.md)

## Context

The existing `flake.nix` builds the jar via `pkgs.maven.buildMavenPackage`, a fixed-output derivation pinned to a specific `mvnHash` of the resolved dependency set — fully offline and reproducible, but the hash must be regenerated by hand whenever dependencies change. ADR 0017 introduces Quarkus for `web-editor`, which pulls in a very large, fast-moving dependency tree; keeping that hash in sync under Nix's offline-build model would be a disproportionate maintenance burden for this project. ADR 0017 also already establishes Docker images as the actual packaging/distribution path for both artifacts.

## Decision

**Scope the Nix flake to `devShell` only** (JDK + Maven, for local building/editing) and **drop `packages.default`/`apps.default`** entirely, for both `cli` and `web-editor`. Nix is how you get the tools to build the project (`nix develop`); it no longer produces a built artifact itself. `docker build` (per-module Dockerfiles, ADR 0017) is the way both artifacts are actually produced and run.

## Alternatives considered

- **Keep Nix packaging for `cli` only** (small dependency tree, no Quarkus), drop it for `web-editor`: considered, but rejected in favor of dropping Nix packaging for both — having one artifact Nix-buildable and the other not would be an inconsistent, surprising split for no real benefit, since Docker already covers both uniformly.
- **Maintain the `mvnHash` across Quarkus upgrades regardless**: rejected — the maintenance cost doesn't pay for itself when Docker already serves the packaging need.

## Consequences

- `flake.nix` keeps only `devShells.default` (`pkgs.jdk` + `pkgs.maven`); `packages.default` and `apps.default` are removed.
- No `mvnHash` to maintain going forward — adding/upgrading dependencies (including Quarkus) no longer requires a Nix-side update.
- Building/running the software locally without Docker still works via plain `mvn` commands inside `nix develop`; there's just no `nix build`/`nix run` shortcut anymore.
